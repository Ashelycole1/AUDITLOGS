# Staging on Vercel (frontend) and Render (backend)

> **Dummy data only.** Vercel and Render are outside Uganda. architecture.md 9 allows them for staging
> only because real audit data never goes there (system.md 4.6 and 4.10). Production runs on the
> server in Uganda. `config.settings.prod` refuses to start on Render, and every hosted page shows a
> "Test system: dummy data only" banner.

```
Browser ──> https://<app>.vercel.app ──(/api/* forwarded)──> https://auditlogs-api.onrender.com
                (React build)                                  (Django + gunicorn, Frankfurt)
                                                                   └── Render Postgres (Frankfurt)
```

The browser only ever talks to the Vercel address. Vercel forwards `/api/*` to Render, so the session
and CSRF cookies are first-party and stay `Secure`, `HttpOnly` and `SameSite=Lax`.

Deploy the backend first, because the frontend forwards to it.

## 1. Backend on Render

1. Push the repository to GitHub.
2. In Render, choose **New, then Blueprint**, pick the repository, and Render reads `render.yaml`. It creates:
   - `auditlogs-staging-db`, a Postgres 16 database (free plan, Frankfurt);
   - `auditlogs-api`, the web service (free plan, Frankfurt).
3. Render asks for the values marked `sync: false`:

   | Variable | Value |
   |---|---|
   | `EVIDENCE_ENCRYPTION_KEY` | Run `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` and paste the output. Keep a copy somewhere safe: without it, uploaded files can't be read. |
   | `CSRF_TRUSTED_ORIGINS` | Your Vercel address, e.g. `https://auditlogs.vercel.app`. You can fill it after step 2 below. |
   | `DEV_SEED_PASSWORD` | A password of your choice, 12 or more characters, for the 7 dummy demo accounts. |
   | `SMTP_*`, `DEFAULT_FROM_EMAIL` | Optional. Leave empty, and sign-in PINs are written to the service's **Logs** tab instead of being emailed. |

   `DJANGO_SECRET_KEY` is generated by Render. Don't type one in.
4. Deploy. Each start runs migrations, creates the demo accounts if they're missing, then starts gunicorn.
5. Check it: `https://auditlogs-api.onrender.com/api/v1/health` should answer `{"status": "ok"}`.

If Render gives the service a different address (for example because the name is taken), change it in
**two** places: `ALLOWED_HOSTS` on Render, and the `/api` destination in `frontend/vercel.json`.

**Free-plan limits, all fine for a dummy-data test:**
- The service sleeps when idle, so the first request takes about a minute.
- The free database expires after 30 days.
- Uploaded evidence is lost on each redeploy, because there's no disk on the free plan.

## 2. Frontend on Vercel

1. In Vercel, choose **Add New, then Project**, and import the same repository.
2. Set **Root Directory** to `frontend`. The framework (Vite), the build command and `dist` come from `frontend/vercel.json`.
3. Under **Environment Variables**, add two variables:
   - `VITE_DEPLOY_ENV` = `staging`, which shows the "dummy data only" banner;
   - `VITE_DATA_SOURCE` = `api`, which makes the screens use the Render backend. Without it, the site runs the in-browser demo.
4. Deploy, then copy the address (e.g. `https://auditlogs.vercel.app`) into `CSRF_TRUSTED_ORIGINS` on Render and redeploy the backend.

`frontend/vercel.json` also sets the security headers:
- a Content Security Policy that only allows the app's own scripts and connections;
- no framing;
- `no-referrer`;
- `noindex`, so search engines keep the test site out.

## 3. Signing in

The demo accounts (Ruth Akello, PIA; Daniel Okello, CIA; Sarah Nabirye, IA; and the others) use `DEV_SEED_PASSWORD`.

After the password step, the 6-digit PIN arrives by email if SMTP is set. If it isn't, find it in Render, under **auditlogs-api, then Logs**, in a line reading *"Your AuditLogs sign-in code is …"*.

## What never changes

- No real names, findings, evidence or exports go into staging. If real data reaches it by mistake, treat it as a breach (design.md 12): record it, delete the Render database and redeploy.
- Production keeps `config.settings.prod`: Postgres in Uganda, the client's SMTP server, and Nginx with TLS. See architecture.md 9.
